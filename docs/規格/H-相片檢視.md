## H. 相片檢視體驗（點圖放大）

**這一節已在本輪實作完成**，下面記錄的是決策與理由，不是待辦。

### 現況壞在哪（三件，都在程式碼與資料上驗證過）

| # | 問題 | 證據 |
|---|---|---|
| 1 | 燈箱只能換張與關閉，**沒有任何放大路徑** | `.lb-stage img{max-width:100%;max-height:100%;object-fit:contain}`。手機上要看細節只剩「下載原圖」 |
| 2 | **每開一次燈箱就從 FTP 重拉一次整張原圖** | `/api/photo/{id}/full` 是 `FtpReadStream` 直通，沒有任何衍生尺寸也沒有快取。資料庫實測：中位數 2.02MB、p95 19.3MB、最大 30.9MB |
| 3 | 換張沒有預載 | `openPhoto()` 每次都是「先塞縮圖 → 等原圖」，前後張完全不預先抓 |

> 第 2 點是真正的瓶頸，而且它跟「有沒有放大」無關。只加縮放不加衍生圖的話，
> 使用者得到的是「可以放大的、每次都要等的燈箱」。

### 決策：引入 PhotoSwipe 5，vendored 進 `/static/vendor/`

MIT、無依賴、54KB（min）＋7KB CSS。**不走 CDN**：CSP 是 `script-src 'self'`，
而且這個服務要能在沒有外網的區網裡開起來 —— 少了外網就連燈箱都壞掉是不可接受的。

**為什麼不自己在 `#lightbox` 上加縮放**：真正的成本不在「放大」這個動作，
而在手勢的慣性、邊界回彈、雙擊在 fit 與 1:1 之間切換、以及 iOS 上自訂 pinch
與頁面本身的縮放互相打架。那些細節做不順使用者立刻有感，而它們已經有人做對了。

### 三個接線決策

**1. 長寬從資料庫來。** PhotoSwipe 要求事先知道每張圖的長寬（否則 slide 的尺寸是 0），
而 `photo` 表本來就有 `width`/`height`，且 `read_info()` 已經依 EXIF orientation
把直式照片的長寬交換過 —— 所以不必等圖載完就能算出 fit 的倍率。

少數讀不到長寬的（壞掉的 EXIF、沒見過的格式）先用 4:3 佔位，載完後用
`naturalWidth` 修正。**只改長寬不夠**：縮放級距是用佔位尺寸算的，不重算的話那張
會一開就是放大而且比例錯（實測停在 0.11 倍）。要照 `calculateSize()` →
`currentResolution = 0` → `zoomAndPanToInitial()` → `applyCurrentZoomPan()` →
`updateContentSize(true)` 這一串走。

**2. 新增 preview 衍生圖（`/api/photo/{id}/preview.jpg`，長邊 1920）。**
這是本節最重要的一項，而且與 PhotoSwipe 無關：把「每次開圖都重拉原圖」換成
「產生一次的本機檔案」。

檔名靠**內容雜湊推算**：縮圖檔名已經是 `p{box}_{sha256(內容)[:24]}.jpg`，雜湊只跟
內容有關，所以「同一張圖的 1920 版叫什麼」把 box 換掉就是（`photo.derived_name()`）。
命中快取時完全不碰 FTP，資料庫也不需要多一個欄位記 preview 檔名。

代價只有第一次點開多一次解碼；`draft()` 已經在 `make_thumb` 裡，1920 長邊約 100–200ms。
原圖比 1920 還小就不產生衍生圖，直接串原圖。

順手修掉一個既有的競態：`make_thumb` 原本直接寫目標檔，而瀏覽器開燈箱時會**同時**
預載前後張 —— 兩個請求真的會同時產生同一個檔名，有機會讀到只寫一半的 JPEG，
而那個壞檔還會被快取住。改成寫暫存檔再 `os.replace`。

**3. 放大超過 preview 實際像素 1.15 倍才換原圖。**
slide 的長寬給的是**原圖**尺寸，所以 1:1 就真的是原圖的 1:1；fit 顯示時看 preview，
要看細節時才付原圖的代價（換 `<img>` 的 src，長寬不變所以版面不跳）。

### EXIF 側欄

PhotoSwipe 沒有這種東西，而拍攝資訊是相片庫的重點，所以自己註冊一個 UI element：
桌機右側 290px、手機底部 40vh、`I` 鍵切換、開合狀態記在 `localStorage`
（讀不到就當展開，不要因為隱私模式就壞掉）。

展開時用 `paddingFn` 把可視區域讓出來，圖不會被壓在面板底下；同時把上排按鈕列與
「下一張」往左推 290px。

> **踩過的坑，寫下來免得再踩**：photoswipe.css 有一條
> `.pswp .pswp__hide-on-close{z-index:10}`，權重壓過 `.pswp__info`，
> 面板會蓋在上排三顆按鈕（i／放大鏡／×）上面 —— 看起來只是按鈕不見，
> 實際是**關不掉**。面板的規則要寫成 `.pswp .pswp__info` 才壓得過。
> 同理，UI element 的 `className` 不要整個覆寫掉，那會連帶拿掉
> `pointer-events` 與淡入淡出。

### 設定

`PHOTO_PREVIEW_PX`（Tier 2、`hot`、預設 1920、範圍 640–6000）。
`/api/photos` 回傳 `preview_px`，**前端不要寫死** —— 寫死的話後台改了設定，
「放到多大該換原圖」那條線就會對不上。

### 刻意不做

| 不做 | 原因 |
|---|---|
| justified／masonry 排版 | 要逐行裝箱，得先有可靠的長寬與多尺寸衍生圖。等 preview 這套穩定再說 |
| 無限捲動 | 會把 E 的換頁捲動修正整個白做，而且相片牆的資料夾切換本來就靠分頁 |
| 縮圖 `srcset` 多尺寸 | preview 一個尺寸已經覆蓋到 4K 螢幕，多做兩個尺寸只是多兩份磁碟檔 |
| GPS 地圖 | `photo.py` 刻意不讀 GPS，這條界線不動 |

### 驗收（已在無頭瀏覽器實測）

| 項目 | 結果 |
|---|---|
| 桌機 fit 顯示 | 1280×800、側欄展開 → 980×653，載入的是 `preview.jpg` |
| 雙擊放大到 1:1 | src 換成 `/full`，`naturalWidth` 由 1920 變 3000 |
| 沒有長寬的照片 | 載完修正成正方形並回到 fit（800×800），不是一開就放大 |
| 手機（390×780） | 底部面板 312px（40vh），圖被限制在上方 468px，箭頭按鈕自動隱藏改用滑動 |
| 鍵盤 | ← → 換張、Esc 關閉、`I` 開合側欄；相片牆縮圖補上 `role/tabindex`，Enter 可開啟 |
| 關閉後 | DOM 清乾淨（`.pswp` 不存在），事件監聽解除，主控台無錯誤 |

**還需要在實機上看的**：iPhone 的雙指捏合與 Safari 網址列的互動。
這一項與 F（iPhone 全螢幕）同一批做實機驗證。
