## B. 管理後台

獨立的 `/admin`，管理者專用，手機可用。

### 分區

| 分區 | 最少要有 |
|---|---|
| **總覽** | 版本與執行時間、影片／相片／容量計數、**磁碟剩餘空間**、最近 10 筆活動、執行中的掃描、待審核人數、**孤兒計數**、問題警示 |
| **媒體庫** | 掃描控制、**完整進度（含目前看不到的相片階段）**、未刮削清單、失敗檔案與錯誤、FTP 目錄瀏覽器 |
| **使用者** | 清單與狀態篩選、核准／拒絕／停權／改角色／**刪除**、**備註欄位**、最後登入來源 |
| **播放與轉碼** | ffmpeg 狀態、硬體加速探測、編碼器深度診斷、轉碼實測、**FTP 併發量測**、GPU、清快取 |
| **系統** | **資料庫狀態**、FTP 測試、TMDB 狀態、**系統參數設定（見 B+）** |
| **紀錄** | **登入稽核（伺服器端分頁）**、掃描日誌、設定變更稽核 |

### 刻意不做

Live TV／DVR、DLNA、外掛系統、自訂角色矩陣、標籤式權限、每人頻寬配額、
家長時段表、CPU/RAM 歷史圖表、Top Users 排行、多伺服器切換、通知渠道大全。

角色維持兩種（管理員／唯讀）。

### 手機版

- 斷點 768px。以上固定側欄，以下漢堡鍵 + 抽屜。
- 抽屜點連結自動關閉；**iOS 不做邊緣滑動開啟**（會跟系統返回手勢打架）。
- 表格換成卡片，**不是**用 CSS 藏欄位（藏起來等於資料消失且無替代入口）。
- 手機保留：看最近錯誤、觸發掃描、停用使用者、看登入紀錄。
- 手機隱藏：清空媒體庫、批次操作、ffmpeg 參數這類寬表單。
- 觸控目標 ≥44×44px；寬內容包在自己的 `overflow-x:auto`，body 永不橫捲。

### 安全與工程

- `/admin` 路由要**自己檢查 `auth.is_admin`** — 中介層只驗登入不驗角色。
- `admin.js` 在 `/static/`，**不需登入就能下載**，不能寫死任何敏感資訊。
- 危險操作二次確認，文案**重述對象名稱**。
- 登入稽核伺服器端分頁，預設 25 筆／頁。
- 每張表要有空狀態與錯誤態。
- 沿用既有 CSS 變數與元件類別（`.file-row` `.pill` `.st` `.chip`）。

## B+. 系統參數設定

同時支援 `.env` 與資料庫。研究了 Immich、Grafana、Gitea、Sonarr、Navidrome、
Nextcloud、Home Assistant 七套的實際做法。

### 核心原則：不要讓兩邊比大小

| 方向 | 最惡毒的失效模式 | 實際案例 |
|---|---|---|
| **env 贏** | **存了但沒生效** — 在後台改值、按存檔、看到成功提示、行為完全沒變，也沒有警告 | Sonarr／Radarr 的原始碼就是這個行為 |
| **DB 贏** | **改 .env 沒反應** — `.env` 是自架使用者唯一熟悉的介面，變成裝飾品之後使用者會認定程式壞了。輪替金鑰時只改 `.env` 以為換好了、實際仍用舊值，是安全事故等級 | Gitea 有一個 issue 正是如此 |

**選 env 贏，但要付 env 贏的稅。** DB 贏的失效模式是安全與復原性硬傷；
env 贏的是純 UX 問題，**而 UX 問題可以用 UI 解決**。
解法不是比大小，是**把「誰在管這一項」變成畫面上看得見的東西**。

### 設定分層（四個機械化問句）

| 問句 | 答「是」 | 例 |
|---|---|---|
| 改錯了會不會讓我連後台都進不去？（或讀它時資料庫還沒連上） | **Tier 0** 只能放 .env | MSSQL 連線、`HOST`/`PORT`、`AUTH_SECRET`、資料目錄、`USER_STORE`/`MEDIA_STORE` |
| 這個值會被當命令、路徑或程式碼執行嗎？（或改它會擴大信任邊界） | **Tier 4** 不放 UI | `FFMPEG_PATH`、`LIBRARY_ROOTS`、`TRUST_PROXY`、`LOCAL_NETWORKS` |
| 洩漏了是外部系統倒楣嗎？ | **Tier 1** 秘密 | `TMDB_API_KEY`、`FTP_PASSWORD`、`GOOGLE_CLIENT_SECRET` |
| 啟動時被拿去建立長生命週期的東西了嗎？ | **Tier 3** 需重啟／重載 | 連線池大小、探測併發數、快取上限 |
| 以上都不是 | **Tier 2** DB + UI，即時生效 | 掃描排除、轉碼參數、遠端畫質、相片門檻、TMDB 語言、字幕預設 |

Tier 2 剛好都是改了立刻生效的 — 這不是巧合，Gitea 遷移設定到後台用的判準就是這條。

> Tier 4 的先例：Navidrome 把轉碼設定 UI 預設關閉，理由寫在安全文件裡 ——
> 「它讓攻擊者可以在你的伺服器上執行任意命令」。`FFMPEG_PATH` 是同一類東西。

### 解析順序與 API

```
.env / 環境變數  >  資料庫  >  程式內建預設值
```

一條規則，全部一致，沒有例外清單。API 不能只回生效值：

```json
{
  "key": "TRANSCODE_CRF",
  "effective": { "value": 21, "source": "env" },
  "candidates": { "env": 21, "db": 23, "default": 21 },
  "locked": true, "shadowed": true,
  "applyMode": "hot", "secret": false
}
```

`shadowed` 一個欄位就解決「.env 改了但 DB 已經有值」的全部歧義。

### UI 規則

- **逐欄位標示鎖定，不是整頁鎖。** Immich 是「有設定檔就整個後台唯讀」，
  50 幾項橫跨四個 tier 全鎖等於後台白做。
- 被鎖：輸入框停用 + 鎖頭 + 「此項由環境變數 `X` 設定，無法在此修改」。
- 被鎖且 shadowed：多一行警示 + `[清除後台儲存值]` 按鈕。
- **絕不能讓停用的欄位送出後才在後端報錯。** Immich 目前就有這個 bug。
- 逐欄位「已修改未儲存」標記 + 「重設為預設值」「重設為上次儲存值」。
- **DB 只存與預設值不同的項目**（相等就刪列）。

### 三態生效方式

| applyMode | 實作要求 | UI |
|---|---|---|
| `hot` | 讀取一律走 `settings.get(key)`，**禁止模組頂層解構成常數** | 「已生效」 |
| `reload` | 先驗證，失敗整批不寫入；成功才寫入並重建子系統 | 「已套用」 |
| `restart` | 只寫入，不套用 | 常駐「需重啟」標記 |

> **最容易悄悄漂移的一項。** 有人在模組頂層寫 `CRF = settings.crf`，那項就從 `hot`
> 退化成 `restart`，**而 UI 仍顯示「已生效」**。要在測試裡釘住。
> 「需重啟」橫幅要能自己消失（比對行程啟動時間與最後變更時間）。

### 秘密

- **唯寫欄位。** API 一律回遮罩 + 「是否已設定」+ 「最後更新時間」，任何情況都不回明文。
- 存 DB 時加密，密文加固定前綴。加密金鑰本身是 Tier 0。
- 支援 `XXX_FILE` 後綴從檔案讀。
- 日誌過濾掛成 logger hook，不在每個呼叫點各自處理。
- **敏感不等於密碼**：MSSQL 主機名、FTP 主機名、媒體目錄絕對路徑都要標敏感，那是內網拓撲情報。
- 秘密進 DB 等於「DB 備份 = 秘密備份」，備份加密要一起決定。

### 其他必要機制

- **啟動時漂移掃描** → 後台橫幅「有 N 項被環境變數覆蓋」。**絕不自動刪 DB 的值。**
- **env 打錯字要抓出來** — `TMDB_API_KAY=xxx` 現在是完全靜默失效的。
- **驗證嚴格度**：`.env` 無效 → 啟動失敗；DB 值無效 → 退回預設並在後台顯示錯誤。
- **CLI 復原路徑** `python -m app.config diff/get/set/unset/list`（後台進不去時唯一救援）。
- **設定變更稽核**：誰、何時、哪一項、從什麼改成什麼。秘密只記「已變更」與時間，
  連遮罩後的值都不記（長度也是情報）。研究的七套**沒有一套**做這件事。
- **別讓後台把自己鎖死**：改綁定位址／對外網址／驗證方式前要二次確認並顯示 CLI 復原指令。

### 區網直連的兩個關卡（運維筆記）

「同網段的筆電打不開 `http://192.168.3.222:29880`」是實際發生過的事，
而且**兩個關卡都不在瀏覽器那一側** —— 調瀏覽器設定不會有用，因為 TCP 根本沒接上。

| # | 關卡 | 症狀 | 處理 |
|---|---|---|---|
| 1 | `HOST=127.0.0.1` | uvicorn 只綁 loopback，**連線直接被拒**（不是超時、不是 403） | 改 `HOST=0.0.0.0` 並重啟。這是唯一的必要條件 |
| 2 | `COOKIE_SECURE=true` | 網頁開得起來，但**登入之後立刻被踢回登入頁** —— Secure cookie 在 `http://` 不會被存 | 三種解：走 https（最好）／區網訪問時關掉它／或用 Chrome 的 `unsafely-treat-insecure-origin-as-secure`。**Safari 沒有等價旗標**，Mac 上只剩前兩種 |
| 3 | Windows 防火牆 | 第 1 項改好還是超時（注意：**超時**，不是拒絕） | 對 29880/TCP 開一條 Private profile 的入站規則 |

診斷順序照著症狀走：**拒絕連線 → 第 1 項；超時 → 第 3 項；登入迴圈 → 第 2 項。**

> 這也正好是「別讓後台把自己鎖死」那一條要防的東西：`HOST` 與 `COOKIE_SECURE`
> 都是 Tier 0／Tier 1，改錯就進不去。後台改這兩項時必須顯示 CLI 復原指令。
